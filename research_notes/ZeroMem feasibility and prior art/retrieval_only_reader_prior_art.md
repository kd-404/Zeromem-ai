# Prior Art: Retrieval-Only / Zero-Parametric-Knowledge Reader Models

## How does this compare to Fusion-in-Decoder (FiD)? What does FiD's reader architecture look like, and does it aim for the same "no memorized knowledge" property?

### Takeaway
FiD (Izacard & Grave, 2020) is a generative reader architecture — independently encode each retrieved passage, fuse via joint decoder attention — but it is initialized from T5, a model pretrained on massive web text, so it retains substantial parametric knowledge by default. FiD's innovation is *architectural efficiency for combining many passages*, not epistemic minimization of memorized facts; the "no memorized knowledge" property is not an explicit design goal of FiD itself, though later work (Atlas) built on FiD's architecture while studying knowledge separation.

### Cited Findings
- FiD independently encodes the question concatenated with each retrieved passage, then concatenates all passage representations and lets the decoder jointly attend over them to generate the answer — avoiding the quadratic self-attention cost of concatenating all passages before encoding. — [A Memory Efficient Baseline for Open Domain QA (Izacard & Grave, 2020)](https://arxiv.org/pdf/2012.15156)
- FiD is initialized from a pretrained T5 sequence-to-sequence model, meaning its weights already encode large amounts of world knowledge from pretraining before any QA fine-tuning. — [GitHub: facebookresearch/FiD](https://github.com/facebookresearch/FiD)
- FiD's architecture outperformed RAG-Sequence by 4–11 points on Natural Questions and TriviaQA, demonstrating the value of encoding many passages independently, but the paper's stated contribution is scalability/efficiency of multi-passage fusion, not suppression of parametric memorization. — [A Memory Efficient Baseline for Open Domain QA](https://arxiv.org/pdf/2012.15156)
- Atlas (Izacard et al., 2022), a later system, explicitly reuses "a sequence-to-sequence model using the Fusion-in-Decoder architecture" as its reader, paired with a Contriever-based dense retriever, and studies few-shot knowledge-intensive tasks — showing FiD's architecture is the substrate later work builds on for knowledge-efficiency questions, but FiD alone was not designed for minimal parametric knowledge. — [Atlas: Few-shot Learning with Retrieval Augmented Language Models (arXiv:2208.03299, 2022)](https://arxiv.org/pdf/2208.03299)

### Inferences
- The proposed "zero parametric knowledge reader" concept is architecturally compatible with (could be built on top of) FiD-style fusion, but is a distinct research question: FiD solves "how do you read many passages efficiently," while the proposed idea targets "how do you make the reader's weights not memorize facts at all." No FiD paper claims the latter property.

### Gaps
- No FiD-specific ablation was found training the reader from scratch (rather than from pretrained T5) to test whether removing pretraining knowledge changes groundedness/faithfulness.

## How does this compare to RETRO (Retrieval-Enhanced Transformer, DeepMind)? Does RETRO's architecture already achieve something like "small model + external knowledge only"?

### Takeaway
RETRO (Borgeaud et al., 2021/2022) achieves GPT-3-comparable performance with 25× fewer parameters by retrieving text chunks from a trillion-token database and fusing them via chunked cross-attention — but RETRO is explicitly a scaling/efficiency technique that *supplements* parametric knowledge with retrieval, not a mechanism to eliminate or suppress parametric memorization. RETRO models still memorize significant facts in weights; retrieval is additive, not a replacement of parametric capacity.

### Cited Findings
- RETRO conditions on document chunks retrieved from a large corpus (web pages, books, news, code); for each ~64-token input chunk it performs nearest-neighbor retrieval and uses the retrieved continuations to help predict the continuation of the input text, via an encoder-decoder Transformer architecture with chunked cross-attention. — [Improving Language Models by Retrieving from Trillions of Tokens (arXiv:2112.04426, 2021)](https://arxiv.org/pdf/2112.04426); [DeepMind blog](https://deepmind.google/blog/improving-language-models-by-retrieving-from-trillions-of-tokens/)
- RETRO achieves performance comparable to GPT-3 and Jurassic-1 on the Pile while using 25× fewer parameters, and the paper frames this explicitly as "decoupling reasoning and memorization" — offloading some memorization burden to the retrieval database rather than model weights. — [Two minutes NLP: RETRO decouples reasoning and memorization](https://medium.com/nlplanet/two-minutes-nlp-how-the-deepmind-retro-model-decouples-reasoning-and-memorization-b393b6a8d07c); [Synced coverage](https://medium.com/syncedreview/deepminds-retro-retrieval-enhanced-transformer-retrieves-from-trillions-of-tokens-achieving-c54313fec51d)
- RETRO is trained on the same trillion-token style corpora used for standard LM pretraining (not knowledge-scrubbed data), so its parameters still absorb substantial factual content during pretraining; retrieval is used to reduce the *training cost* of achieving high performance (smaller model, same capability) rather than to enforce zero memorization. — [DeepMind blog: "RETRO uses an external database to reduce the training cost without shrinking the training sample size"](https://deepmind.google/blog/improving-language-models-by-retrieving-from-trillions-of-tokens/)
- Language modeling performance improves continuously as retrieval database size increases (tested up to 2 trillion tokens), reinforcing that RETRO treats retrieval as a scaling lever, not an epistemic constraint. — [arXiv:2112.04426](https://arxiv.org/pdf/2112.04426)

### Inferences
- RETRO is often cited informally as "small model + external knowledge," but this is a mischaracterization for the proposed idea's purposes: RETRO's smaller models are smaller because retrieval substitutes for *some* capacity needed for memorization-heavy tasks, not because training was designed to prevent memorization. A RETRO checkpoint can still hallucinate ungrounded facts from parametric memory; nothing forces it to rely on retrieved chunks specifically. This is a materially different design target than "reader with deliberately near-zero parametric factual knowledge."

### Gaps
- Found no RETRO ablation studies measuring how much of RETRO's factual accuracy comes from parametric vs. retrieved knowledge (e.g., a counterfactual-retrieval or closed-book RETRO experiment).

## How does this compare to extractive QA models (SQuAD-style BERT readers)? Is the proposed idea just extractive QA rebranded with generation and citations added?

### Takeaway
Extractive readers (BERT/RoBERTa-for-QA) are close in spirit — small, passage-conditioned, span-selection rather than free generation — but they are typically pretrained on the same large web/book corpora as generative models (so they still carry substantial parametric knowledge from pretraining), and they lack multi-passage synthesis, citation formatting, and abstention/faithfulness mechanisms. The proposed idea differs from "extractive QA rebranded" mainly in (a) explicit training-time suppression of parametric knowledge (not just architectural span-extraction) and (b) generative synthesis with citations across multiple chunks, which extractive span models cannot do by construction.

### Cited Findings
- Extractive models predict a span of the input document as the answer (e.g., via BERT), while generative readers (e.g., T5, BART) sequence-to-sequence generate an answer from the question and document; a systematic, controlled comparison using the same pretrained backbones (T5 and BART, extractive vs. generative heads) had been "largely unexplored" until the 2022 SPANLP workshop paper below. — [Choose Your QA Model Wisely: A Systematic Study of Generative and Extractive Readers for QA (arXiv:2203.07522, 2022)](https://arxiv.org/pdf/2203.07522)
- ColBERT-QA (base), an extractive/retrieval-focused reader, outperforms other BERT-base-reader models on multiple open-domain QA datasets and even outperforms generative RAG on TriviaQA "despite using far fewer parameters and being restricted to extractive reading" — showing small extractive readers can be very competitive without needing generation. — [Relevance-guided Supervision for OpenQA with ColBERT (arXiv:2007.00814)](https://arxiv.org/pdf/2007.00814)
- RAG (Lewis et al., 2020) demonstrated that neither a re-ranker nor an extractive reader is strictly necessary for state-of-the-art open-domain QA, combining closed-book generation flexibility with open-book retrieval performance — implying the field moved toward generative readers partly for answer flexibility (paraphrase, synthesis across passages) that pure span extraction cannot provide. — [Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks (arXiv:2005.11401, 2020)](https://arxiv.org/pdf/2005.11401)
- Standard extractive QA readers (BERT-for-QA, RoBERTa-SQuAD) are fine-tuned versions of models pretrained via masked language modeling on large general corpora (Wikipedia, BookCorpus, or larger web-scale data for RoBERTa) — this pretraining is exactly the channel through which parametric factual knowledge is absorbed, so extractive readers are not knowledge-free by design; they are merely constrained at inference time to output spans from the given passage, which limits (but does not eliminate) opportunities for the model's prior knowledge to leak into the answer choice among candidate spans.

### Inferences
- Extractive QA's span-restriction is a *behavioral* constraint (the output must be a contiguous substring of the context), not a *representational* one (the weights can still be full of memorized facts influencing which span looks "right"). This is a meaningfully different mechanism from training a model whose weights themselves are deliberately impoverished of memorized facts. The proposed idea is therefore not merely a rebrand of extractive QA — it targets the training/pretraining objective and representation, not just the output format — though it is fair to note extractive QA is the closest structural analog in output discipline (grounded-in-context answers) and any claim of true novelty should explicitly acknowledge this lineage and articulate the training-time distinction, since a reviewer would otherwise flag the overlap.

### Gaps
- No direct study found that measures how often extractive QA models select a factually-plausible-but-context-unsupported span due to parametric bias (i.e., a "parametric leakage into span selection" quantification). This would be useful counter-evidence or supporting evidence for the "extractive QA rebranded" critique.

## Is there published research explicitly about training/evaluating models for faithfulness or groundedness by deliberately minimizing memorized parametric knowledge?

### Takeaway
Yes — this is an active and directly relevant research area with multiple 2022-2026 papers, and one paper in particular, "Knowledgeless Language Models" (2026), is near-identical in spirit to the proposed idea: it deliberately trains base language models to suppress parametric factual recall (via named-entity anonymization during pretraining) specifically to make them better evidence-grounded/RAG-suited models. This substantially undercuts a claim of novelty for "train a model to have minimal memorized knowledge so it relies on context" as a general concept, though the exact packaging (as a discrete small RAG "reader component" with citations) is less directly covered by this specific line of work.

### Cited Findings
- **"Knowledgeless Language Models: Suppressing Parametric Recall for Evidence-Grounded Language Modeling"** (Cohen, Carré, Lechtenbörger, Droste, Kerschke, Biswas, de Melo, Buys; arXiv:2607.12831, posted July 2026) trains "KLLMs" by anonymizing named entities in pretraining corpora (replacing them with type-tagged placeholders like `EntX`, using a Flair NER model with the OntoNotes taxonomy, ~87% entity-mention recall, while preserving numbers/dates for coherence), explicitly to remove "a primary channel for entity-linked factual supervision." — [arXiv:2607.12831](https://arxiv.org/abs/2607.12831), [HTML version](https://arxiv.org/html/2607.12831)
- KLLMs are tested across SmolLM (135M, 360M, 1.7B) and LLaMA (1B, 3B) model families at 2.5B/10B/20B pretraining tokens, and show "near-complete collapse of closed-book factual recall" (tested on LAMA, SQuAD, Natural Questions) while preserving or improving performance on contextual QA, FEVER fact verification, HaluBench hallucination detection, and commonsense reasoning (CommonsenseQA, StrategyQA, PIQA). — [arXiv:2607.12831 HTML](https://arxiv.org/html/2607.12831)
- KLLMs "consistently outperform standard language models in evidence-grounded regimes, including retrieval-augmented and retrieval-trained setups," with 20-25% relative improvement under imperfect/incomplete retrieval evidence, and better calibration (ECE, Brier score, AUROC) — directly supporting the proposed thesis that deliberately knowledge-suppressed models make better RAG components. — [arXiv:2607.12831](https://arxiv.org/abs/2607.12831)
- **DisentQA** (Neeman et al., ACL 2023, arXiv:2211.05655) trains QA models via counterfactual data augmentation to explicitly disentangle and separately predict a "contextual answer" vs. a "parametric answer," improving robustness to context-vs-memory knowledge conflicts on Natural Questions — a training-time approach to separating (not eliminating) parametric knowledge, aimed at interpretability/trust rather than shrinking the model's knowledge itself. — [DisentQA (arXiv:2211.05655)](https://arxiv.org/abs/2211.05655); [ACL Anthology](https://aclanthology.org/2023.acl-long.559/); [code](https://github.com/ellaneeman/disent_qa)
- **"Faithfulness-QA: A Counterfactual Entity Substitution Dataset for Training Context-Faithful RAG Models"** (Ju, Wang, Zhang; arXiv:2604.25313, April 2026) builds a 99,094-sample dataset from SQuAD/TriviaQA by substituting answer-bearing named entities with type-consistent alternatives from a 76,953-entity bank, "manufacturing controlled knowledge conflicts between context and parametric memory," explicitly to give models training signal that rewards preferring context over internal knowledge. — [arXiv:2604.25313](https://arxiv.org/abs/2604.25313)
- **"Trusting Your Evidence: Hallucinate Less with Context-aware Decoding"** (Shi, Han, Lewis, Tsvetkov, Zettlemoyer, Yih; arXiv:2305.14739, 2023/NAACL 2024) proposes context-aware decoding (CAD) — an inference-time contrastive decoding technique (no retraining) that amplifies output-probability differences between with-context and without-context generation, achieving up to 14.3% factuality gains for LLaMA on summarization and improving faithfulness for OPT/GPT/LLaMA/FLAN-T5. This is a decoding-time alternative to training-time knowledge suppression — same goal (favor context over parametric memory), different mechanism (no architecture/training change). — [arXiv:2305.14739](https://arxiv.org/abs/2305.14739); [code](https://github.com/xhan77/context-aware-decoding)
- **"Knowledge Conflicts for LLMs: A Survey"** (EMNLP 2024, arXiv:2403.08319) taxonomizes context-memory, inter-context, and intra-memory conflicts, and categorizes existing mitigation strategies into "faithful-to-context" (context-prioritizing) vs. "discriminating misinformation" (parametric-trusting) strategies — this is the standard survey/vocabulary for the exact problem space the proposed idea sits in, and is a must-cite framing paper. — [arXiv:2403.08319](https://www.emergentmind.com/papers/2403.08319); [EMNLP version](https://aclanthology.org/2024.emnlp-main.486/); [GitHub survey repo](https://github.com/pillowsofwind/Knowledge-Conflicts-Survey)
- Roberts et al. (2020) established the "closed-book QA" framing itself: closed-book QA evaluates factual knowledge stored purely in a model's parameters (no external resource access), versus open-book/retrieval-augmented QA — the standard terminology underlying all of the above. — [arXiv:2008.02637](https://arxiv.org/pdf/2008.02637)
- Related but distinct: "LLMs' Reading Comprehension Is Affected by Parametric Knowledge and Struggles with Hypothetical Statements" (arXiv:2404.06283, 2024) evaluates reading comprehension using fictitious/counterfactual entities specifically to isolate linguistic/reasoning ability from parametric knowledge interference, showing current LLMs still let parametric knowledge bleed into supposedly context-only answers on hypothetical/non-affirmative statements. — [arXiv:2404.06283](https://arxiv.org/html/2404.06283v2)

### Inferences
- The "Knowledgeless Language Models" paper (2026) is the single closest piece of prior art found for the proposed system's core claim. It differs from the proposed system mainly in framing (a general pretraining methodology for LMs of various sizes and families, evaluated broadly) rather than (per the assignment's description) a purpose-built small reader *component* explicitly packaged for RAG pipelines with citation output. A novelty claim should be scoped narrowly — e.g., "packaging a knowledge-suppressed small model specifically as a drop-in RAG reader with citation formatting and abstention behavior" — rather than the broader claim that training a model to not memorize facts is itself new.
- The field increasingly treats "faithfulness/groundedness via reduced parametric reliance" as a well-established, named research direction (knowledge conflicts, context-faithfulness, closed-book-vs-open-book), with both training-time (entity anonymization, counterfactual substitution, disentanglement) and inference-time (context-aware decoding) approaches published. Any pitch of the proposed system should differentiate on packaging/engineering (small dedicated component, specific citation UX, integration into a RAG pipeline) rather than the underlying epistemic-suppression concept.

### Gaps
- Could not find a paper that specifically frames a knowledge-suppressed model as a discrete, publicly released "RAG reader component" product/checkpoint (as opposed to a research methodology/paper) — this may be a genuine gap the proposed system could fill from a productization standpoint, even though the underlying training methodology is not new.
- Did not verify whether "Knowledgeless Language Models" (arXiv:2607.12831) has since been published at a peer-reviewed venue (it appears to be a 2026 arXiv preprint at time of writing); peer-review status should be re-checked before citing it as an accepted result.

## Are there any small (<100M parameter) open-source "citation" or "grounded QA" models released specifically as RAG components?

### Takeaway
The closest published, purpose-built examples are the Pleias-RAG model family (350M and 1B parameters — just above the 100M threshold specified) from PleIAs, which are small models mid-trained specifically to natively emit citations/literal quotes for RAG use cases and explicitly marketed as small, RAG-dedicated reader-style models. True sub-100M dedicated "citation RAG reader" checkpoints are hard to find as a distinct released product category; most sub-100M open models in this space are general-purpose encoders (e.g., extractive QA or embedding models) rather than generative grounded-answer-with-citation models.

### Cited Findings
- Pleias-RAG-350m and Pleias-RAG-1B (PleIAs, arXiv:2504.18225, April 2025) are "mid-trained on a large synthetic dataset emulating the retrieval of a wide variety of multilingual open sources from the Common Corpus" and provide "native support for citation and grounding with literal quotes," generating citations via `<ref>` tags directly at inference time, along with RAG-workflow features like query routing, query reformulation, and source reranking. — [Even Small Reasoners Should Quote Their Sources: Introducing the Pleias-RAG Model Family (arXiv:2504.18225)](https://arxiv.org/abs/2504.18225); [Hugging Face paper page](https://huggingface.co/papers/2504.18225)
- Pleias-RAG-350m and -1B outperform other small language models (SLMs) below 4B parameters on HotPotQA and 2wiki RAG benchmarks and are reported competitive with much larger models (Qwen-2.5-7B, Llama-3.1-8B, Gemma-3-4B) while claimed to be "the only SLMs to date maintaining consistent RAG performance across leading European languages" with systematic reference grounding. — [arXiv:2504.18225](https://arxiv.org/abs/2504.18225); [summary via X/Rohan Paul](https://x.com/rohanpaul_ai/status/1923202744833409464)
- For sub-100M-parameter models generally, the BabyLM Challenge explicitly targets the 10M–100M parameter range for architectural research, but this is a general LM-training-efficiency benchmark, not a citation/grounded-QA-specific effort. — [general BabyLM context via search results]
- ColBERT-QA (base) and other BERT-base extractive readers (~110M parameters, e.g. PubMedBERT) are close to the 100M threshold and are "grounded" in the sense of extracting spans from context, but are not marketed or released as generation-with-citation RAG components — they predate and differ from the citation/quote-based framing popularized by Self-RAG/Pleias-RAG. — [Relevance-guided Supervision for OpenQA with ColBERT (arXiv:2007.00814)](https://arxiv.org/pdf/2007.00814)
- Self-RAG (Asai et al., arXiv:2310.11511, 2023) is a training framework (not itself a single small model) that teaches an arbitrary LM to emit "reflection tokens" — retrieval tokens (should I retrieve?) and critique tokens (is this passage relevant/supported/useful?) — enabling controllable, self-evaluated grounded generation; it has been applied to 7B/13B base models in the original paper, not sub-100M, but the reflection-token mechanism is architecture-agnostic and could in principle be applied to a much smaller reader. — [Self-RAG (arXiv:2310.11511)](https://arxiv.org/abs/2310.11511); [project page](https://selfrag.github.io/)

### Inferences
- There is no widely-known, dedicated open-source sub-100M-parameter model released purely as a "citation/grounded-QA RAG component" — the smallest purpose-built examples (Pleias-RAG-350m) sit modestly above that threshold. This suggests a small window of genuine novelty in the *exact* parameter range and packaging the proposed system describes, even though the surrounding techniques (citation tagging, knowledge suppression, reflection tokens) are each independently published.

### Gaps
- Could not confirm any released checkpoint strictly under 100M parameters that is both (a) generative (not extractive-span-only) and (b) natively citation-emitting for RAG use, as of this research pass — this may be worth a follow-up targeted search on Hugging Face model hub filters (parameter count < 100M, tag: RAG or citation) rather than general web search, which returned mostly papers rather than hub listings.
- Did not independently verify Pleias-RAG's exact training corpus size or confirm whether it applies any parametric-knowledge-suppression technique (e.g., entity anonymization) during its own pretraining/mid-training — the search results only describe its citation mechanism and benchmark performance, not its epistemic training objective.
